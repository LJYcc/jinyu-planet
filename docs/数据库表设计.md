# 金鱼星球 MySQL 表设计（Prisma 版）

## 1. 这份文档和 Prisma 的关系

金鱼星球使用 MySQL 和 Prisma ORM。

- `prisma/schema.prisma`：表、字段、关系、索引的唯一结构来源。
- `prisma.config.ts`：Prisma 7 CLI 的配置文件，保存 schema 路径、migration 路径、seed 命令和连接 URL 的读取位置。
- `prisma/migrations/`：每次表结构变更的历史记录，由 Prisma 生成并提交 Git。
- MySQL：migration 实际执行后，真正保存数据的数据库。
- `server/utils/prisma.ts`：Nuxt 服务端创建并复用 Prisma Client 的入口。

不要用 Navicat 手动新建或修改这些表。若要改字段，先改 `schema.prisma`，再由 Prisma 生成 migration。

## 2. 首版范围

首版持久化匿名访客、会话、主题、帖子、标签和图片元数据。没有登录、浏览量统计、评论、点赞、订阅或 AI 会话历史表。浏览量、点赞和评论数据及其相关接口纳入第二期规划。

```text
anonymous_visitors 1 -- n visitor_sessions
anonymous_visitors 1 -- n posts
topics             1 -- n posts
posts              1 -- n post_images
posts              n -- n tags (through post_tag_links)
```

## 3. Model 与 MySQL 表映射

| Prisma model       | MySQL 表             | 用途                                                         |
| ------------------ | -------------------- | ------------------------------------------------------------ |
| `AnonymousVisitor` | `anonymous_visitors` | 匿名昵称和访客状态，不保存真实姓名或联系方式。               |
| `VisitorSession`   | `visitor_sessions`   | 匿名 Cookie 对应的令牌哈希、过期与撤销状态。                 |
| `Topic`            | `topics`             | 星球主题配置。                                               |
| `Post`             | `posts`              | 帖子的类型、正文、摘要、作者、状态、发布时间和首页精选配置。 |
| `Tag`              | `tags`               | 帖子补充标签。                                               |
| `PostTagLink`      | `post_tag_links`     | 帖子与标签的多对多关系。                                     |
| `PostImage`        | `post_images`        | 对象存储图片的键、URL、替代文本和排序。                      |

`schema.prisma` 通过 `@map` 和 `@@map` 保持代码名称与数据库名称的稳定映射。例如代码中写 `post.createdAt`，数据库列实际为 `created_at`。

## 4. 关键字段与规则

### 匿名访客和会话

- `AnonymousVisitor.nickname` 保存类似“会发光的金鱼0427”的当前公开昵称；帖子通过 `visitor_id` 关联访客并展示当前昵称，访客更换昵称后历史帖子也会显示新昵称。
- `VisitorSession.tokenHash` 只保存随机会话令牌的 SHA-256 哈希，设置为唯一。
- 浏览器未来只持有 HttpOnly Cookie，不能提交或伪造 `visitorId`。
- `blocked` 状态为以后处理滥用保留；首版不提供后台管理界面。

### 帖子

- `Post.type`：`article`、`short`、`photo`、`link`。
- `Post.status`：`pending`、`published`、`hidden`。首版 API 可默认发布，但上线前必须确认审核策略。
- `Post.isFeatured` 标记帖子是否由站长选入首页精选；`featuredRank` 控制精选展示顺序，数值越小越靠前。首页只读取 `published` 帖子，精选不足 4 条时用最新公开帖子补齐；首版不提供匿名访客修改这两个字段的 API。
- `contentHtml` 保存服务端消毒后的 wangEditor HTML；`contentText` 是从 HTML 派生的纯文本，用于搜索、摘要和阅读时长。
- `clientNonce` 是浏览器在一次发布请求中生成的 UUID；与 `visitorId` 联合唯一，避免网络重试或重复点击产生重复帖子。
- `slug` 是公开详情页 URL 的唯一标识，例如 `/posts/my-first-signal`。

### 图片和标签

- 图片二进制不存入 MySQL；对象存储保存文件，`PostImage` 只保存 `storageKey`、`publicUrl`、`altText` 和尺寸信息。
- `PostTagLink` 的复合主键 `(post_id, tag_id)` 防止同一个标签重复挂到同一篇帖子。
- 当前没有图片上传 API，`PostImage` 是为后续对象存储接入预留的表。

## 5. 迁移步骤

先确认 Prisma 和 Client 版本一致，完成依赖安装后：

0. Prisma 7 的 Nuxt 运行时还需要 MySQL driver adapter。安装与 Prisma Client 相同的版本：

   ```bash
   npm install @prisma/adapter-mariadb@7.10.0
   ```

1. 从 `.env.example` 复制出本地 `.env`，填写真实 MySQL 连接串：

   ```env
   DATABASE_URL="mysql://用户名:密码@主机:3306/数据库名"
   ```

   Prisma 7 的 `migrate dev` 还需要一个独立的空 shadow database。将它配置在 `.env`：

   ```env
   SHADOW_DATABASE_URL="mysql://用户名:密码@主机:3306/数据库名_shadow"
   ```

   `DATABASE_URL` 和 `SHADOW_DATABASE_URL` 不能指向同一个数据库。阿里云用户没有 `CREATE DATABASE` 权限时，可以在控制台或 Navicat 手动创建一次 `数据库名_shadow`，再给当前开发用户授予这个数据库的建表、修改表和删除表权限；不需要给用户全局 `CREATE DATABASE` 权限。

2. 确认 MySQL 数据库使用 `utf8mb4` 字符集和合适的 Unicode 排序规则，保证中文昵称、标题和正文正确保存。

3. Prisma CLI 会从 `prisma.config.ts` 读取 `DATABASE_URL`。验证 schema：

   ```bash
   npx prisma validate
   ```

4. 创建并执行首个 migration：

   ```bash
   npx prisma migrate dev --name initial_schema
   ```

   这一步才会真正创建表，并生成 `prisma/migrations/.../migration.sql`。

5. 生成 TypeScript 可用的 Prisma Client：

   ```bash
   npx prisma generate
   ```

6. 写入五个初始主题：

   ```bash
   node prisma/seed.mjs
   ```

生产环境不运行 `migrate dev`，只部署已提交的 migration：

```bash
npx prisma migrate deploy
```

## 6. API 和数据表

| API                            | Prisma model                         | 说明                                                        |
| ------------------------------ | ------------------------------------ | ----------------------------------------------------------- |
| `POST /api/visitors/bootstrap` | `AnonymousVisitor`、`VisitorSession` | 创建/恢复匿名 Cookie 会话。                                 |
| `PATCH /api/visitors/nickname` | `AnonymousVisitor`                   | 更换当前访客昵称。                                          |
| `GET /api/topics`              | `Topic`                              | 返回按顺序启用的主题。                                      |
| `GET /api/posts`               | `Post`、`Topic`、`AnonymousVisitor`  | 只返回已发布帖子，支持主题、关键词和 page/pageSize 分页。   |
| `GET /api/posts/featured`      | `Post`、`Topic`、`AnonymousVisitor`  | 返回首页最多 4 条精选帖子，按人工排序并以最新公开帖子补齐。 |
| `GET /api/posts/:slug`         | `Post`、`Topic`、`Tag`、`PostImage`  | 返回公开详情与相关推荐。                                    |
| `POST /api/posts`              | `VisitorSession`、`Post`、`Tag`      | 校验会话，消毒正文，计算摘要后持久化。                      |
| `POST /api/uploads`（后续）    | `PostImage`                          | 上传到对象存储后记录图片元数据。                            |
| `POST /api/ai/chat`（后续）    | 无需表                               | 服务端代理千问，默认不保存会话。                            |

所有已实现 API 的成功响应均为 `{ success: true, data, metadata? }`；分页等辅助信息位于 `metadata`。失败响应均为 `{ success: false, code, message }` 并保留正确 HTTP 状态码，避免客户端依赖路由各自定义的错误结构。

## 7. 不能只靠数据库约束的规则

MySQL/Prisma 表结构确保关系和唯一性，但以下规则必须由 Nuxt API 实现：

- 长文必须有标题和正文；短帖不保存标题，最多 500 字，并从正文首句派生列表标题。
- 图文标题可选，但必须有图文说明；链接分享必须有合法 HTTP/HTTPS URL 和标题，推荐语可选。
- wangEditor HTML 必须在服务端消毒，禁止脚本、事件属性和危险 URL。
- 匿名访客有发布频率限制；上线前需要决定直接发布还是先进 `pending`。
- 图片的 MIME 类型、文件大小、数量和对象存储访问权限需要在上传 API 校验。

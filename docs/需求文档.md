# 金鱼星球（Goldfish Planet）需求文档

## 1. 项目定位

金鱼星球（Goldfish Planet）是一个开放、轻盈、有个人气质的中文网页社区。它由站长发起，但不只记录站长的生活和想法，也允许每一位路过的人留下文字、观点和小小的发现。

它不是需要注册和经营人设的社交平台，也不是作品集或企业官网。金鱼星球更像一颗可以短暂停靠的数字星球：阅读、发帖、聊天，然后带走一点有意思的东西。

### 首版个人定位文案（可随时替换）

**中文短句：** 把想说的话，投进一颗小小的星球。

**中文介绍：** 这里收集没有标准答案的想法、在生活里捡到的片段，以及愿意被陌生人读到的一点真心。你可以安静看看，也可以留下自己的坐标。

**英文辅助文案：** A small planet for thoughts worth leaving behind.

### 首版目标

- 建立有辨识度、适合长时间浏览的个人网站首页。
- 让访客不登录也能获得一个临时昵称，并发布公开帖子。
- 支持浏览、筛选、阅读帖子，并通过富文本写作表达完整内容。
- 在全站提供 AI 助理入口，跳转至独立的通用 AI Chat 页面，并通过服务端安全调用千问。
- AI Chat 先完成通用对话闭环，再以已发布帖子为知识来源逐步增加站内问答能力；模型密钥始终只保留在服务端。

## 2. 首版范围与非范围

### 本期包含

- 公开首页、帖子广场、帖子详情、发帖页、AI Chat 页面、关于页面。
- 匿名访客昵称生成与本地记忆。
- 帖子浏览、主题筛选、搜索、全站 Header 搜索入口、富文本撰写、发布成功反馈。
- 首页精选内容、星球主题、社区新信号等内容模块。
- 桌面端与移动端响应式设计。

### 本期不做

- 登录、注册、密码、个人账号中心和权限体系。
- 邮件订阅、周刊、付费、私信、浏览量统计、点赞、评论和关注关系。
- 帖子图片的发布和展示、正式内容审核后台。
- RAG 站内知识检索、长期记忆、未经白名单约束的自动写入或管理操作；联网搜索仅按 AI Chat Phase 6.3 的千问能力边界接入。
- 作品集页面。站点暂时没有作品时，不应为了填充页面而伪造作品项目。

### 后续阶段规划

- 第二期纳入帖子浏览量记录、点赞和评论能力，并根据实际数据评估热门内容排序。
- 第二期互动功能上线前，需要补充对应的数据表、接口、权限校验、反滥用策略和前端状态反馈。

## 3. 用户与身份规则

### 3.1 用户类型

| 用户 | 身份方式                     | 能做什么                                   |
| ---- | ---------------------------- | ------------------------------------------ |
| 游客 | 首次进入时自动获得临时昵称   | 浏览、搜索、发帖、使用 AI Chat             |
| 站长 | 与普通游客相同的公开浏览体验 | 后续接入数据服务后，再单独补充内容维护能力 |

首版没有登录按钮、头像上传、个人主页或“我的帖子”中心。每位访客只保留一个浏览器本地昵称；清除浏览器数据或更换设备后会生成新的昵称。

匿名访客身份由浏览器 Cookie 中的会话令牌证明。会话默认有效期为 30 天；访客回访时，只有会话剩余时间不超过 3 天，才将同一个令牌的 Cookie 与服务端会话同时续期至未来 30 天。Cookie 在 HTTPS 请求中设置 `Secure`，通过 HTTP 访问开发或临时 IP 预览时不设置该属性，以确保浏览器能够保存会话。若访客连续 30 天未访问，Cookie 和服务端会话都会过期，下次访问将创建新的匿名身份；原身份发布的帖子仍保留原作者归属，但新身份不能再编辑或管理这些帖子。

### 3.2 随机昵称机制

访客首次进入网站时，系统自动生成“有趣中文前缀 + 中文名词 + 四位数字”的昵称，并写入浏览器本地存储。每次回访沿用原昵称，保证在当前设备上有基础辨识度。

昵称风格应轻松、带一点星球气质，不使用真实姓名或攻击性词汇。推荐的生成规则：

| 组成     | 示例词库                                             | 生成示例 |
| -------- | ---------------------------------------------------- | -------- |
| 气质前缀 | 漂流的、熬夜的、慢吞吞的、会发光的、路过的、爱发呆的 | 会发光的 |
| 星球名词 | 金鱼、月球、云朵、陨石、汽水、信号灯、树洞、纸飞机   | 金鱼     |
| 编号     | `0001` - `9999`                                      | 0427     |

示例昵称：`会发光的金鱼0427`、`路过的纸飞机1980`、`慢吞吞的月球0314`、`爱发呆的信号灯6712`。

昵称应在发帖页清晰展示，并提供“换一个昵称”按钮。更换昵称会更新该匿名访客在历史和后续帖子中的展示昵称，但不会改变帖子所属的匿名访客身份；首版不提供手动自由输入昵称，避免不当内容和冒名。

## 4. 视觉与内容气质

以 `docs/主页ui.webp` 为主要视觉参考，保留其“暗色沉浸式首屏、浅色编辑排版内容区、深色信息带、少量暖黄色强调”的节奏；不直接复制模板的栏目、图文或商业化文案。

- **首屏：** 深色全幅背景与低对比遮罩，优先传达“金鱼星球”和个人定位。使用 Logo 资源作为品牌识别，Logo 采用未来科技方向：以抽象金鱼流线、行星核心、轨道和信号节点组成标记，避免卡通吉祥物感；背景可先使用可替换的自然/夜空占位图。
- **内容区：** 白色、浅灰和细分割线组织阅读，不使用大量悬浮卡片。
- **强调色：** 使用一款偏暖的黄色，服务于主按钮、活跃导航和主题标记；Element Plus 组件不得使用默认蓝色。
- **字体：** 中文正文使用本地 Noto Sans SC；英文展示文字、日期和编号可使用本地 Source Sans 3 或简洁等宽字体，营造“星球档案”感。
- **图像：** 图片是内容的一部分，不作无意义装饰；所有图片提供替代文本，并保持稳定的裁切比例。
- **移动端：** 发帖和阅读优先。按钮、输入框、悬浮 AI 入口均需单手可触达，不能遮挡正文或系统安全区。
- **滚动条：** 页面与局部可滚动区域统一使用 AI Chat 的细窄半透明暖黄色圆角滚动条，轨道透明。

前端实现使用 Element Plus 作为 UI 组件框架。Vue 文件中的局部样式使用 `<style scoped lang="scss">`；全局样式只承载 reset、设计 token、字体入口、容器和可复用工具类。Logo、图标和 favicon 使用项目本地资源，不依赖第三方字体或图片 CDN。当前科技版资源为 `app/assets/logo/goldfish-planet-logo-tech.png`、`app/assets/logo/goldfish-planet-logo-light-tech.png`、`app/assets/logo/goldfish-planet-icon-tech.png` 和 `public/favicon-goldfish-planet-tech.ico`；组合 Logo 保留科技版图案，中文与英文文字参照 `goldfish-planet-logo-light-imagegen-v6.png` 的圆润粗体风格，不使用中间黄色横线，图案保持原始宽高比，图标可见高度明显高于文字，并收紧透明画布中的有效内容区域。

星球广场列表区的当前 UI 参考 `app/assets/images/call_LaPowHL1o6S40D5FsBMoUT0T.png` 和 `app/assets/images/call_cWfiMNN1m5hR02idVsiJN1dD.png`。这组参考只用于广场内容区，不替换帖子页顶部既有的首屏背景和首屏结构。

帖子详情页的当前 UI 参考 `app/assets/ui/ui-post-detail-page.png`。该参考采用深色上下文返回带、正文主栏和右侧信息栏，不包含左侧阅读目录或重复返回入口。

## 5. 信息架构

| 页面       | 建议路径       | 作用                                                         |
| ---------- | -------------- | ------------------------------------------------------------ |
| 首页       | `/`            | 认识金鱼星球、查看精选内容和最新社区信号                     |
| 星球广场   | `/posts`       | 全部公开帖子，支持筛选和搜索                                 |
| 帖子详情   | `/posts/:slug` | 阅读完整帖子及相关主题内容                                   |
| 投递新信号 | `/write`       | 访客以匿名昵称撰写并发布帖子                                 |
| AI Chat    | `/ai-chat`     | 独立的通用 AI 对话体验，通过服务端调用千问；后续接入站内知识 |
| 关于星球   | `/about`       | 站点由来、站长简介占位文案、使用说明和联系入口               |

主导航：首页、星球广场、投递新信号、关于星球。桌面端显示主导航和搜索入口，不显示 Header 右侧的发帖 CTA、登录、注册或账号入口；点击搜索图标打开固定高度的搜索弹窗，输入关键词后直接查询公开帖子列表，每次请求最多 100 条，结果区域独立滚动；Dialog 内容容器不设置内边距，搜索输入与结果内容各自保留阅读留白，使滚动条贴住弹窗右边缘；滚动条始终预留固定宽度，非悬停时仅隐藏滑块，避免悬停时内容宽度变化；弹窗打开时锁定页面滚动，Header 保持原有视口宽度，AI 助理使用视口左侧坐标定位，不依赖 right 补偿且不使用运行时宽度计算。移动端不显示折叠菜单按钮，核心入口由页面内容提供。AI 助理不占用主导航，始终固定在右下角。

## 6. 首页需求

### 6.1 首屏

- 展示品牌名“金鱼星球 / GOLDFISH PLANET”。
- 展示本文件第 1 节的定位文案，后续站长可替换。
- 主按钮为“进入星球广场”，跳转 `/posts`；次级文本入口为“投递新信号”，跳转 `/write`。
- Header 从页面加载开始固定在顶部：首页首屏使用透明深色模式；普通页面滚动或进入非首页后使用浅色背景、深色 Logo 和深色导航文字，切换过程平滑且不改变布局高度。AI Chat 使用独立全屏页面，不显示站点 Header。
- 横向菜单不显示 Element Plus 默认的 active 下划线；Logo 位于左侧，主导航和搜索入口组成右侧操作区。

### 6.2 内容模块

首页使用以下模块丰富内容，不使用作品集、订阅或周刊：

| 模块       | 内容                                                                | 目的                         |
| ---------- | ------------------------------------------------------------------- | ---------------------------- |
| 星球自述   | 站点介绍、站长短简介占位、外部链接占位                              | 告诉访客这是怎样的地方       |
| 精选信号   | 1 条大推荐 + 3 条次推荐帖子；优先人工精选，不足时以最新公开帖子补齐 | 给新访客可立即阅读的内容入口 |
| 星球主题   | 4 至 6 个主题及简述                                                 | 帮助内容聚合和探索           |
| 最新着陆   | 最新公开帖子时间流                                                  | 体现网站持续有内容流动       |
| 漂流瓶提示 | 引导访客使用随机昵称写下第一条内容                                  | 将浏览自然转化为参与         |

初始主题建议：`生活碎片`、`技术与产品`、`城市观察`、`脑内宇宙`、`好东西分享`、`山与日出`。主题为可替换的站点配置，不应写死在页面文本中。

精选信号由站长通过受信任的数据维护流程配置。帖子使用 `isFeatured` 标记是否进入精选，并使用 `featuredRank` 控制展示顺序，数值越小越靠前；首页仅读取已发布帖子，按精选顺序最多展示 4 条，数量不足时按发布时间倒序补齐。首版不向匿名访客提供修改精选状态或排序的公开接口。

当没有真实帖子时，界面应使用少量明确标记为“示例内容”的占位稿，或使用温和的空状态引导访客发出第一条信号；上线前替换为真实内容。

## 7. 星球广场与帖子阅读

### 7.1 星球广场 `/posts`

- 按发布时间倒序展示公开帖子。
- 主卡和列表行显示：主题、标题、摘要、发布时间、阅读时长、封面缩略图（如有）。署名昵称在帖子详情页元信息中展示。
- 支持按主题筛选，并支持关键词搜索标题、摘要与正文文本。
- Header 中的全站搜索入口以固定高度弹窗直接搜索公开帖子；搜索结果区域独立滚动，不跳转星球广场或写入 URL。广场内部的主题筛选、关键词搜索、最新/精选切换和分页直接应用到当前列表状态，不持续写入 URL 或堆叠浏览器历史。
- 支持“最新”和“精选”排序；“最新”按发布时间倒序展示，“精选”只展示已发布且标记为精选的帖子，并按 `featuredRank` 升序、发布时间倒序排列。
- 首期不记录浏览量，也不使用点赞、评论等互动数据进行排序；热门内容排序属于第二期规划。
- 内容区顶部使用搜索框、主题选择和“最新/精选”切换组成的工具栏，不单独设置旧版左侧筛选面板。
- 当前筛选结果的第 1 条作为横向主卡展示，其余帖子从第 2 条开始进入列表，不能在主卡和列表中重复展示。
- 广场使用 flex 两栏布局；左侧内容区使用约 800px 的固定高度，工具栏固定在顶部，下面的结果容器占满剩余空间并使用 flex 布局，主卡自身不设置固定高度，图片与正文采用 flex 横向排列，区块标题垂直居中并保留上下约 10px 内边距，帖子列表自身使用纵向 flex 排列，列表区块按正常流式顺序排列，分页器在底部对齐，不覆盖列表内容。主卡不额外渲染隐藏主题节点，右侧本周主题图片直接使用图片元素，不添加仅用于样式的包装节点。有数据但不足 6 条时，缺少的卡片位置保留空白，不添加骨架或虚假内容；完全无数据时显示 `el-empty`。仅在总页数大于 1 时渲染分页器，但分页区域始终保留固定高度；列表区域不额外显示公开信号总数总结。切换分页时保留上一页内容直到新数据返回，避免页面闪动。
- “最新”模式下主卡标题为“最新抵达”、列表标题为“继续探索”；“精选”模式下主卡标题为“精选信号”、列表标题为“更多精选”。
- 桌面端内容区采用主列表加右侧信息栏的两列布局；右侧展示本周主题、星球状态和投递新信号入口。移动端改为纵向排列。
- 右侧“本周主题”从启用主题表中按周随机选择，同一周内保持一致，跨周自动切换；主题名称和描述使用数据库中的真实数据。
- 星球状态必须通过公开的 `/api/planet/stats` API 读取真实数据：星球成员为 active 匿名访客数，信号总数为已发布帖子数，本周新增为本周一 00:00 起已发布的帖子数；接口失败时不显示伪造数字。
- 内容较多时使用传统页码分页，API 通过 `page` 和 `pageSize` 控制当前页与每页数量，单次请求最多 100 条；Header 搜索弹窗为避免二次翻页固定请求 100 条。
- 无搜索结果、无某主题内容、加载中和加载失败都应有完整状态。

### 7.2 帖子详情 `/posts/:slug`

- 显示主题、标题、署名昵称、发布时间、阅读时长与富文本正文；封面图仅用于星球广场列表/主卡展示，详情正文不再单独渲染封面；详情不单独展示摘要（摘要仅用于列表卡片），标题区采用紧凑的信息层级，减少主题、标题和元信息之间的垂直留白；详情使用普通内容容器渲染，保留编辑器支持的安全内容结构与格式（文字样式、颜色、字号字体、行高、H1-H6 标题、段落、对齐缩进、列表、表格、代码块、链接、图片、视频和分割线），与编辑器中的排版一致；表格保留编辑器输出的宽度，使用相同的固定表格布局、单元格内边距、边框和表头样式，不额外撑宽单元格；引用保留编辑器中的浅色背景、左侧强调线和内边距，链接保持可识别并可安全打开。
- 首版不显示文章目录或阅读导航；当前发布编辑器没有目录锚点和滚动高亮能力，不能展示与实际内容脱节的假导航。
- 详情页顶部使用紧凑的深色星夜上下文带，提供唯一的“返回星球广场 / 信号详情”入口；从星球广场进入详情后返回时，应恢复进入详情前的搜索、主题、排序、页码和滚动位置状态；桌面端高度约为 126px，移动端约为 118px；不在正文左侧重复设置返回按钮。
- 详情区域只显示当前帖子的正文内容，不展示右侧推荐、信号信息或投递入口。正文使用约 960px 的居中阅读栏，并固定为顶部背景带之后的首屏剩余高度；正文超出时仅内容区内部滚动，继续向下滚动可看到 footer。标题区采用紧凑的信息层级，减少主题、标题、摘要和元信息之间的垂直留白，并将标题字号限制在桌面端 42px 以内。
- 正文中的图片按编辑位置展示，外部链接（如有）显示在正文底部。
- 允许复制链接分享；首期不记录浏览量，不提供评论、点赞或收藏；相关互动能力纳入第二期规划。
- 外部链接默认新窗口打开，并具有安全属性。

## 8. 匿名发帖与富文本编辑器

### 8.1 投递新信号 `/write`

### 8.2 富文本能力

所有帖子共享一套富文本编辑器，首版需要：

- 标题、段落、一级至六级标题；加粗、下划线、斜体、删除线、行内代码、上下标、波浪下划线、着重号和清除格式。

- 无序列表、有序列表、待办列表、代码块（含语言选择）和表格。
- 链接插入与编辑、外部图片插入和正文图片上传；外部链接须有安全提示。
- 支持插入可直接播放的 HTTP/HTTPS 视频地址；视频文件上传不在首期范围内，避免未完成存储、关联和公开访问链路的内容丢失。
- 封面图和正文内图片均可上传 JPEG、PNG、WebP 或 GIF，单个文件不超过 20 MB；上传内容先归属当前匿名访客，发布时才关联到帖子并通过公开帖子图片地址读取。

服务端统一将信号保存为文章类型，生成消毒后的富文本 HTML、纯文本、摘要和阅读时长；客户端不可以提交作者、状态、发布时间或存储地址。

### 8.3 匿名内容边界

匿名发布不会因“不登录”而降低安全要求。首版界面和后续服务接入都应遵循：

- 发布前提示“请勿发布个人隐私、违法或攻击性内容”。
- 为帖子数据预留 `公开`、`待处理`、`隐藏` 状态；当前演示阶段可直接显示发布成功，但正式接库前必须确定内容审核策略。
- 限制单条内容长度、标签数量和发布频率，防止滥用。
- 昵称不等于真实身份，页面不展示设备信息或精确位置。

## 10. 数据与技术接入边界

### 10.1 API 响应契约

所有 Nuxt 服务端 API 使用统一 JSON 响应格式。成功响应为 `{ success: true, data, metadata? }`，其中 `data` 为业务数据，`metadata` 仅承载分页、是否首次创建等辅助信息；失败响应为 `{ success: false, code, message }`，并保留匹配的 HTTP 状态码。`code` 是供前端分支处理的稳定机器可读代码，`message` 为可展示的简短说明；匿名会话令牌、数据库内部字段和未处理异常详情不得出现在响应中。

### 10.2 服务端验证与授权边界

受保护路由先通过 Nitro server middleware 解析并验证匿名会话 Cookie，缺失或失效时返回 HTTP 401 与稳定错误代码，并将已验证身份放入请求上下文；路由只读取认证上下文，不重复验证 token。若受保护路由未配置认证中间件，公共身份读取工具返回明确的服务器配置错误。公开读取接口不要求会话。JSON 请求体的读取和格式错误处理由公共工具完成，字段、长度和业务规则仍由对应领域的验证模块实现。首版没有账号角色或后台权限，但资源归属和权限断言使用统一授权工具；后续接入 Bearer Token、管理员角色或资源编辑能力时，在认证后、业务写入前执行对应验证并返回 HTTP 403。

站长已具备部署平台、数据库和图片存储，但将在后续阶段逐步接入。因此首版前端需要采用可替换的数据边界：

- 页面不依赖登录态才能工作。
- 帖子、主题、昵称和 AI 消息使用清晰的数据模型；AI 请求由服务端适配器调用千问，浏览器不直接接触供应商凭据。
- 发布、图片上传、帖子查询、搜索和 AI 请求都应封装为可替换的数据调用点；站内知识问答通过检索结果组成受限上下文，不把全部数据库内容发送给模型。
- 浏览器端普通 API 请求统一封装在 `app/services/`，页面和组件通过 service 或 composable 调用，不直接重复编写 `$fetch`；AI 流式请求保留读取响应流所需的原生 `fetch`。
- 不在界面、代码库或演示数据中写入部署密钥、数据库凭据或模型密钥。
- 文件上传通过受匿名会话保护的本站 API 完成，浏览器不直接获得对象存储凭据。私有阿里云 OSS Bucket 对 JPEG、PNG、WebP、GIF、PDF、DOCX、CSV、TXT 执行 MIME 白名单、文件签名和单文件 20 MB 校验，将对象存入按用途与访客隔离的键空间；数据库只记录对象键、校验后的 MIME、大小、哈希和归属，不记录永久公开 URL。AI 图文消息已接入：图片仅经短期签名 URL 提供给视觉模型，文档提取的前 24,000 个字符按片段提供给模型；用户预览 DOCX、CSV、TXT 时从私有 OSS 提取全文并直接返回，不将预览全文写入数据库。

- 每页有独立标题、描述与社交分享图片配置位；提供站点地图和 robots 配置位。
- 首屏图和帖子图片使用响应式尺寸与延迟加载，避免大图影响首屏体验。
- 常见移动尺寸下无横向滚动、文字重叠或被悬浮按钮遮挡的内容。
- 样式按页面和组件归属维护：首页专属样式放在首页 Vue 文件，Header、Footer 和布局样式放在对应组件，全局文件只保留通用规则。

## 12. 首版验收标准

1. 访客进入首页后，可看见“金鱼星球 / GOLDFISH PLANET”、定位文案、主导航和清晰的内容入口。
2. 访客首次进入会获得中文加数字的随机昵称，刷新和再次访问保持一致；可主动更换昵称。
3. 访客可以从 `/write` 完成“填写标题和主题 -> 富文本编辑、可选上传封面 -> 本地草稿 -> 预览 -> 发布成功”的体验流程，无需登录。
4. 星球广场可浏览帖子、按主题筛选、搜索关键词并进入详情页；详情页能够正确呈现富文本内容。
5. 除 `/ai-chat` 外的公开页面右下角都有 AI 助理入口，点击后到达 `/ai-chat`；配置服务端密钥后，聊天页能通过本站 API 获得真实千问回复，未配置时明确提示服务不可用。
6. 首页不包含作品集、邮件订阅和周刊模块，改以精选信号、星球主题、最新着陆和发帖引导丰富页面。
7. 桌面端和移动端的核心阅读、写作、AI 跳转流程可用且布局稳定；移动端不依赖 Header 折叠菜单完成核心路径。

## 13. 后续再讨论的事项

- 实际个人介绍、头像、首屏背景、社交链接、联系信息和站点文案替换。
- 帖子是否在真实服务接入后直接公开，还是先进入待处理状态。
- 正文内图片说明、替代文本编辑和多图排序规则。
- 千问模型、额度、超时、错误重试、站内检索和会话清理策略。
- 第二期评论、点赞、浏览量统计和访客个人主页等功能的具体规则、展示方式与上线范围。
- 帖子标签推荐：管理员可将标签标记为热门/推荐，并通过人工排序控制推荐顺序；发帖页下拉先展示未隐藏的热门标签，再展示普通已有标签，同时保留输入新标签后创建并关联的能力。标签需增加 `isFeatured`、`sortOrder`、`isHidden` 等治理字段，并补充对应读取接口和受信任的维护流程。
- 当前 `POST /api/posts` 的发布限流使用服务端进程内 `Map` 保存访客记录；后续需要清理长期过期的访客 key，避免服务持续运行时内存增长，并在多实例或 Serverless 部署时评估改用 Redis 等共享存储。

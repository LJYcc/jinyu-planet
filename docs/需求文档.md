# 金鱼星球（Goldfish Planet）需求文档

## 1. 项目定位

金鱼星球（Goldfish Planet）是一个开放、轻盈、有个人气质的中文网页社区。它由站长发起，但不只记录站长的生活和想法，也允许每一位路过的人留下文字、观点和小小的发现。

它不是需要注册和经营人设的社交平台，也不是作品集或企业官网。金鱼星球更像一颗可以短暂停靠的数字星球：阅读、发帖、聊天，然后带走一点有意思的东西。

### 首版个人定位文案（可随时替换）

**中文短句：** 把想说的话，投进一颗小小的星球。

**中文介绍：** 这里收集没有标准答案的想法、在生活里捡到的片段，以及愿意被陌生人读到的一点真心。你可以安静看看，也可以留下自己的坐标。

**英文辅助文案：** A small planet for thoughts worth leaving behind.

### 首版目标

- 建立有辨识度、适合长时间浏览的个人网站首页。
- 让访客不登录也能获得一个临时昵称，并发布公开帖子。
- 支持浏览、筛选、阅读帖子，并通过富文本写作表达完整内容。
- 在全站提供 AI 助理入口，跳转至独立的通用 AI Chat 页面。
- 首版以网页体验和交互为核心，为后续接入数据库、图片存储和千问 SDK 留出接口位置。

## 2. 首版范围与非范围

### 本期包含

- 公开首页、帖子广场、帖子详情、发帖页、AI Chat 页面、关于页面。
- 匿名访客昵称生成与本地记忆。
- 帖子浏览、主题筛选、搜索、富文本撰写、发布成功反馈。
- 首页精选内容、星球主题、社区新信号等内容模块。
- 桌面端与移动端响应式设计。

### 本期不做

- 登录、注册、密码、个人账号中心和权限体系。
- 邮件订阅、周刊、付费、私信、点赞、评论和关注关系。
- 真实数据库、图片对象存储、正式内容审核后台。
- 千问 SDK 的实际调用、会话云端保存、联网搜索。
- 作品集页面。站点暂时没有作品时，不应为了填充页面而伪造作品项目。

## 3. 用户与身份规则

### 3.1 用户类型

| 用户 | 身份方式                     | 能做什么                                   |
| ---- | ---------------------------- | ------------------------------------------ |
| 游客 | 首次进入时自动获得临时昵称   | 浏览、搜索、发帖、使用 AI Chat             |
| 站长 | 与普通游客相同的公开浏览体验 | 后续接入数据服务后，再单独补充内容维护能力 |

首版没有登录按钮、头像上传、个人主页或“我的帖子”中心。每位访客只保留一个浏览器本地昵称；清除浏览器数据或更换设备后会生成新的昵称。

匿名访客身份由浏览器 Cookie 中的会话令牌证明。会话默认有效期为 30 天；访客回访时，只有会话剩余时间不超过 3 天，才将同一个令牌的 Cookie 与服务端会话同时续期至未来 30 天。若访客连续 30 天未访问，Cookie 和服务端会话都会过期，下次访问将创建新的匿名身份；原身份发布的帖子仍保留原作者归属，但新身份不能再编辑或管理这些帖子。

### 3.2 随机昵称机制

访客首次进入网站时，系统自动生成“有趣中文前缀 + 中文名词 + 四位数字”的昵称，并写入浏览器本地存储。每次回访沿用原昵称，保证在当前设备上有基础辨识度。

昵称风格应轻松、带一点星球气质，不使用真实姓名或攻击性词汇。推荐的生成规则：

| 组成     | 示例词库                                             | 生成示例 |
| -------- | ---------------------------------------------------- | -------- |
| 气质前缀 | 漂流的、熬夜的、慢吞吞的、会发光的、路过的、爱发呆的 | 会发光的 |
| 星球名词 | 金鱼、月球、云朵、陨石、汽水、信号灯、树洞、纸飞机   | 金鱼     |
| 编号     | `0001` - `9999`                                      | 0427     |

示例昵称：`会发光的金鱼0427`、`路过的纸飞机1980`、`慢吞吞的月球0314`、`爱发呆的信号灯6712`。

昵称应在发帖页清晰展示，并提供“换一个昵称”按钮。更换昵称只影响之后发布的内容，不修改既有帖子署名。首版不提供手动自由输入昵称，避免不当内容和冒名。

## 4. 视觉与内容气质

以 `docs/主页ui.webp` 为主要视觉参考，保留其“暗色沉浸式首屏、浅色编辑排版内容区、深色信息带、少量暖黄色强调”的节奏；不直接复制模板的栏目、图文或商业化文案。

- **首屏：** 深色全幅背景与低对比遮罩，优先传达“金鱼星球”和个人定位。背景可先使用可替换的自然/夜空占位图。
- **内容区：** 白色、浅灰和细分割线组织阅读，不使用大量悬浮卡片。
- **强调色：** 使用一款偏暖的黄色，服务于主按钮、活跃导航和主题标记。
- **字体：** 中文正文优先清晰易读；英文、日期、编号可采用简洁的等宽或展示字体，营造“星球档案”感。
- **图像：** 图片是内容的一部分，不作无意义装饰；所有图片提供替代文本，并保持稳定的裁切比例。
- **移动端：** 发帖和阅读优先。按钮、输入框、悬浮 AI 入口均需单手可触达，不能遮挡正文或系统安全区。

## 5. 信息架构

| 页面       | 建议路径       | 作用                                           |
| ---------- | -------------- | ---------------------------------------------- |
| 首页       | `/`            | 认识金鱼星球、查看精选内容和最新社区信号       |
| 星球广场   | `/posts`       | 全部公开帖子，支持筛选和搜索                   |
| 帖子详情   | `/posts/:slug` | 阅读完整帖子及相关主题内容                     |
| 投递新信号 | `/write`       | 访客以匿名昵称撰写并发布帖子                   |
| AI Chat    | `/ai-chat`     | 独立的通用 AI 对话体验，后续接千问 SDK         |
| 关于星球   | `/about`       | 站点由来、站长简介占位文案、使用说明和联系入口 |

主导航建议：首页、星球广场、投递新信号、关于星球。AI 助理不占用主导航，始终固定在右下角。

## 6. 首页需求

### 6.1 首屏

- 展示品牌名“金鱼星球 / GOLDFISH PLANET”。
- 展示本文件第 1 节的定位文案，后续站长可替换。
- 主按钮为“进入星球广场”，跳转 `/posts`；次级文本入口为“投递新信号”，跳转 `/write`。
- 顶部导航在首屏上以浅色显示；页面滚动后转为固定的浅色导航，保证可读性。

### 6.2 内容模块

首页使用以下模块丰富内容，不使用作品集、订阅或周刊：

| 模块       | 内容                                   | 目的                         |
| ---------- | -------------------------------------- | ---------------------------- |
| 星球自述   | 站点介绍、站长短简介占位、外部链接占位 | 告诉访客这是怎样的地方       |
| 精选信号   | 1 条大推荐 + 3 条次推荐帖子            | 给新访客可立即阅读的内容入口 |
| 星球主题   | 4 至 6 个主题及简述                    | 帮助内容聚合和探索           |
| 最新着陆   | 最新公开帖子时间流                     | 体现网站持续有内容流动       |
| 漂流瓶提示 | 引导访客使用随机昵称写下第一条内容     | 将浏览自然转化为参与         |

初始主题建议：`生活碎片`、`技术与产品`、`城市观察`、`脑内宇宙`、`好东西分享`。主题为可替换的站点配置，不应写死在页面文本中。

当没有真实帖子时，界面应使用少量明确标记为“示例内容”的占位稿，或使用温和的空状态引导访客发出第一条信号；上线前替换为真实内容。

## 7. 星球广场与帖子阅读

### 7.1 星球广场 `/posts`

- 按发布时间倒序展示公开帖子。
- 每条帖子显示：主题、标题或首句、摘要、昵称、发布时间、阅读时长、封面缩略图（如有）。
- 支持按主题筛选，并支持关键词搜索标题、摘要与正文文本。
- 支持“最新”和“推荐”排序；推荐为展示层标记，数据接入后由站长配置。
- 内容较多时使用传统页码分页，API 通过 `page` 和 `pageSize` 控制当前页与每页数量，不能一次性加载全部内容。
- 无搜索结果、无某主题内容、加载中和加载失败都应有完整状态。

### 7.2 帖子详情 `/posts/:slug`

- 显示主题、标题、署名昵称、发布时间、阅读时长、封面图（如有）与富文本正文。
- 长文章显示可收起的目录；短帖不显示空目录。
- 正文底部显示相同主题的推荐阅读和返回广场入口。
- 允许复制链接分享；首版不做评论、点赞或收藏。
- 外部链接默认新窗口打开，并具有安全属性。

## 8. 匿名发帖与富文本编辑器

### 8.1 投递新信号 `/write`

- 页面顶部显示当前随机昵称和“换一个昵称”操作。
- 可选择帖子类型：`长文`、`短帖`、`图文`、`链接分享`。
- 可选择一个主题；允许补充少量标签。
- 发表按钮清晰显示为“投递到金鱼星球”。
- 发布前校验必填内容；发布后展示成功反馈和“查看帖子/继续浏览”入口。

### 8.2 富文本能力

所有帖子共享一套富文本编辑器，首版需要：

- 标题、段落、一级至三级标题。
- 加粗、斜体、删除线、引用、分割线。
- 无序列表、有序列表、待办列表、代码块。
- 链接插入与编辑；外部链接须有安全提示。
- 图片插入、图片说明和替代文本。真实上传服务暂未接入时，图片功能可使用明确的界面占位和本地预览。
- 撤销/重做、草稿本地自动保存、离开页面时的未保存提示、发布前预览。

短帖可不填标题，列表页以正文第一行作为主标题；长文必须填写标题和正文。内容应存为结构化编辑器数据，后续接入数据库时不依赖仅保存 HTML 字符串。

### 8.3 匿名内容边界

匿名发布不会因“不登录”而降低安全要求。首版界面和后续服务接入都应遵循：

- 发布前提示“请勿发布个人隐私、违法或攻击性内容”。
- 为帖子数据预留 `公开`、`待处理`、`隐藏` 状态；当前演示阶段可直接显示发布成功，但正式接库前必须确定内容审核策略。
- 限制单条内容长度、标签数量和发布频率，防止滥用。
- 昵称不等于真实身份，页面不展示设备信息或精确位置。

## 9. AI 助理与 AI Chat

### 9.1 全站入口

- 公开页面右下角固定展示 AI 助理按钮，使用消息/星球类图标及“AI 助理”短文字。
- 悬停或长按显示“和 AI 聊聊”。
- 点击后直接跳转 `/ai-chat`，不在当前页弹出聊天窗。
- 后台不存在时，入口在所有页面显示；移动端需避开安全区和其他悬浮操作。

### 9.2 AI Chat 页面 `/ai-chat`

- 页面包含欢迎语、建议问题、消息流、多行输入框、发送按钮、生成中状态和新建对话入口。
- 定位为通用 AI Chat：用户可以问任何问题，不局限于金鱼星球的站内内容。
- 后续由站长接入千问 SDK。页面现在应按真实聊天产品设计好消息状态，不能用编造回答伪装已经接入 AI。
- 必须包含空状态、输入为空、请求中、停止生成、接口报错与重新发送等状态。
- 首版将对话保存在当前浏览器会话或用演示数据呈现；云端会话历史、登录同步和长期记忆不在本期范围。
- 在发送区域附近展示简短提示：请勿输入密码、身份证号等敏感信息；AI 回答可能有误，请自行判断。

## 10. 数据与技术接入边界

站长已具备部署平台、数据库和图片存储，但将在后续阶段逐步接入。因此首版前端需要采用可替换的数据边界：

- 页面不依赖登录态才能工作。
- 帖子、主题、昵称和 AI 消息使用清晰的数据模型，初期可由本地演示数据与浏览器存储驱动。
- 发布、图片上传、帖子查询、搜索和 AI 请求都应封装为可替换的数据调用点，后续可连接已有数据库、对象存储和千问 SDK。
- 不在界面、代码库或演示数据中写入部署密钥、数据库凭据或模型密钥。

## 11. 通用质量要求

- 所有页面提供加载、空状态、错误状态和 404 页面。
- 支持键盘导航，输入控件有清晰标签和焦点状态，图片具有替代文本，文本对比度足够。
- 每页有独立标题、描述与社交分享图片配置位；提供站点地图和 robots 配置位。
- 首屏图和帖子图片使用响应式尺寸与延迟加载，避免大图影响首屏体验。
- 常见移动尺寸下无横向滚动、文字重叠或被悬浮按钮遮挡的内容。

## 12. 首版验收标准

1. 访客进入首页后，可看见“金鱼星球 / GOLDFISH PLANET”、定位文案、主导航和清晰的内容入口。
2. 访客首次进入会获得中文加数字的随机昵称，刷新和再次访问保持一致；可主动更换昵称。
3. 访客可以从 `/write` 完成“选类型和主题 -> 富文本编辑 -> 本地草稿 -> 预览 -> 发布成功”的体验流程，无需登录。
4. 星球广场可浏览帖子、按主题筛选、搜索关键词并进入详情页；详情页能够正确呈现富文本内容。
5. 所有公开页面右下角都有 AI 助理入口，点击后到达 `/ai-chat`；聊天页包含完整交互状态但不假装已接入模型。
6. 首页不包含作品集、邮件订阅和周刊模块，改以精选信号、星球主题、最新着陆和发帖引导丰富页面。
7. 桌面端和移动端的核心阅读、写作、AI 跳转流程可用且布局稳定。

## 13. 后续再讨论的事项

- 实际个人介绍、头像、首屏背景、社交链接、联系信息和站点文案替换。
- 帖子是否在真实服务接入后直接公开，还是先进入待处理状态。
- 图片上传的格式、大小、数量限制与存储路径。
- 千问 SDK 的具体接入方式、模型选型、额度、超时、错误重试与会话持久化策略。
- 评论、点赞、访客个人主页等社交功能是否在后续版本加入。

# Task 9：AI Chat 会话、历史与流式服务

**描述：** 在千问服务端直连的基础上，将 AI Chat 升级为可持久化的匿名访客会话，并直接实现流式回答。前端每次只提交当前消息和幂等 nonce；后端根据会话归属读取历史、调用千问、保存消息并流式返回。新会话采用延迟创建，点击“新建对话”只进入未保存状态，用户第一次发送消息时才创建数据库会话。高级能力按 Phase 6 的阶段推进；帖子 RAG 和 Agent 工具仍不在本任务范围。

## Phase 1：数据模型与匿名会话归属

**实现内容：**

- 新增 `AiConversation` 和 `AiMessage` Prisma 模型。
- 会话关联当前 `AnonymousVisitor`；消息关联会话。
- 一个匿名访客可以创建多个会话。
- AI 历史跟随匿名会话的 30 天访问周期；Cookie 过期或更换设备后，新身份不能读取旧历史。
- 用户消息使用 `clientNonce` 幂等，避免网络重试产生重复消息。
- 新增会话删除能力，删除会话时级联删除消息。

## Phase 2：后端会话 API

**实现内容：**

- `POST /api/ai/conversations`：保留显式创建能力，前端延迟创建流程默认在第一次发送时调用。
- `GET /api/ai/conversations`：读取当前匿名访客的会话列表。
- `GET /api/ai/conversations/:id/messages`：读取当前访客拥有的历史消息。
- `DELETE /api/ai/conversations/:id`：删除当前访客拥有的会话。
- `PATCH /api/ai/conversations/:id`：修改当前访客拥有的会话标题或置顶状态。
- `POST /api/ai/conversations/:id/messages`：只接收当前消息和 `clientNonce`，由服务端读取历史并调用模型。
- 所有会话接口都通过服务端匿名会话校验，不信任客户端提交的 `visitorId` 或消息 `role`。

## Phase 3：流式回答

**实现内容：**

- 千问请求使用 `stream: true`。
- 服务端读取上游流并以浏览器可消费的流式响应转发。
- 流式响应使用空闲超时，收到新的上游片段后重新计时，不因持续输出超过固定总时长而中断。
- 前端创建空的 assistant 消息，收到片段后逐步追加。
- 前端按统一的 16ms 渲染节奏追加每个思考或答案流片段；不按字符数计算等待时间，避免长内容产生累积延迟。思考阶段不显示输入光标，最终答案生成期间在答案末尾显示闪烁输入光标，停止、失败或完成后移除光标。
- assistant 消息尚未收到首个思考或答案流式字符时，不渲染空白消息气泡，只在 AI 标签下方显示等待光标；思考内容出现后隐藏等待光标，最终答案内容出现后才在答案末尾显示光标。
- user 消息在请求开始时保存；assistant 消息在流式完成后保存完整内容。
- 中断或失败时不伪造完整回答；保留 user 消息，允许用户使用同一 nonce 重试。

## Phase 4：前端会话状态

**实现内容：**

- 前端保存当前 `conversationId`，`messages` 只用于页面展示，不再作为完整请求参数。
- 点击“新建对话”时只清空当前页面并进入未保存状态，不立即创建空会话。
- 用户第一次发送消息时才创建会话，成功后保存 `conversationId`。
- 会话标题使用首条 user 消息的前 160 个字符；前端在首次发送时立即同步侧栏标题，服务端持久化相同标题。
- 支持加载会话列表、切换会话、加载历史和删除会话。
- 首次加载历史会话列表时，侧边栏显示会话条目骨架并禁用会话操作；URL 带会话参数时，右侧 Header 的单条骨架和内容区 Loading 都在会话列表加载期间显示。列表返回后，URL 恢复和侧边栏切换均立即使用本地会话列表中的目标标题；历史消息加载状态继续控制右侧内容，隐藏旧消息并在撑满消息区、带 `rgba(0, 0, 0, 0.1)` 背景的居中 Loading 层中等待，同时暂时禁用输入。加载失败后恢复原会话内容并展示错误状态。
- 页面刷新或首次进入聊天页时默认展示新对话，不自动选中第一条历史会话；历史仍可由访客手动选择。
- AI Chat URL 包含 `conversation` 查询参数且该会话属于当前匿名访客时，页面自动加载对应历史消息并保留该参数；用户从侧边栏切换会话或首次发送创建会话后，同步以替换方式更新该参数，因此刷新页面仍会恢复当前会话。点击“新建对话”、删除当前会话，或参数对应的会话不存在、格式不正确、不属于当前访客时，清除该参数并保持新对话。当前“分享”只复制该受权限保护的会话定位链接，不提供跨匿名访客的公开阅读。
- AI Chat 页面内容容器局部使用 `1280px` 宽度；全站默认内容容器仍为 `1180px`。
- `/ai-chat` 使用独立全屏页面，不使用站点默认 Header、Footer 或 AI 悬浮入口；页面本身禁止滚动，消息区域和历史会话列表负责各自的局部滚动。
- AI Chat 侧边栏展开状态的品牌 Logo 可点击返回首页 `/`。
- 新对话空状态使用现有小鱼 Logo、居中欢迎语、简短提问、带主题色图标的建议问题和输入框；欢迎内容相对面板中心轻微上移。AI Chat 输入框不显示字数统计，使用上下两行布局，文本输入在上、发送或停止按钮在下方右侧。发送和停止按钮保持相同固定尺寸，按钮图标使用稍大的 `19px` 尺寸；停止生成使用 Element Plus `danger` 底色，并提供危险色悬停和键盘聚焦反馈。历史会话的底部输入框复用相同的盒子样式和上下布局；发送成功进入已有会话后，恢复该底部输入框位置与交互。
- 聊天面板使用固定视口高度；消息区域和历史会话列表分别局部滚动，新建对话按钮不随历史列表滚动。
- 发送新消息时消息区域自动滚动到底部并跟随流式回答；访客主动滚动消息区域后暂停自动跟随，滚回底部后恢复跟随。
- 侧边栏和内容区头部固定为 48px；侧边栏支持折叠，折叠切换使用平滑过渡。折叠后 header 只保留带 Tooltip 的展开图标，内容区域只保留带 Tooltip 的新建对话图标。
- 内容区头部只显示当前标题，点击标题进入行内编辑并通过 PATCH 接口保存。
- 历史会话使用三点菜单提供重命名、置顶、分享、多选和删除；多选模式平滑显示复选框，并在底部提供批量置顶和删除。
- 折叠状态不显示访客昵称；展开且非多选状态下侧边栏底部显示当前匿名访客昵称，多选状态下底部切换为批量置顶和删除按钮。
- 侧边栏与内容区为两个独立的半透明深色面板，均使用 `12px` 圆角，面板间距固定为 `5px`，背景不使用模糊滤镜。
- 置顶会话在历史列表顶部单独显示为“置顶”分组；未置顶会话按“今天”“昨天”“7天内”“30天内”和 `YYYY-MM` 月份分组展示，月份倒序排列。日期边界使用 moment 按自然日计算，标题旁不额外显示置顶图标。
- AI 消息展示小鱼头像和无背景消息内容，用户消息使用独立气泡；消息区域与历史列表使用细窄、半透明的自定义滚动条。
- AI 回复使用关闭原始 HTML 的标准 Markdown 渲染，支持标题、段落、强调、列表、引用、分隔线、表格、行内代码、围栏代码块和安全链接；已识别语言的代码块需要高亮且支持横向滚动。用户消息保持纯文本展示。
- 消息气泡由 `ai-message-content` 统一分发内容：当前字符串接口下，assistant 文本进入 Markdown 渲染，user 文本保持纯文本；后续图文内容数组按 `type` 扩展，不把图片或文件强行编码为 Markdown 文本。Markdown 样式和 Mermaid 交互由 `ai-markdown-content` 自己维护，聊天容器只负责消息布局。
- 纯前端 Markdown 增强支持 KaTeX 公式、Mermaid 图表和 TOML 代码高亮。KaTeX 兼容 `$...$`、`$$...$$`、`\\(...\\)` 与 `\\[...\\]` 分隔符，围栏代码和行内代码中的字面量不得被公式解析改写。Mermaid 只处理标记为 `mermaid` 的围栏代码块，使用严格安全模式并在无滚动条、固定宽高、图表居中的独立边框画布中展示；面板提供缩小、放大、还原和下载 PNG，鼠标位于画布内时可滚轮缩放、按住左键拖拽平移，缩放和位移只改变画布内 SVG，不改变画布尺寸，公式和宽图在窄屏可横向滚动。
- 发送、停止、失败和重试流程使用 `async/await`，代码中不使用 `void` 异步调用写法。

## Phase 5：代码可读性与验证

**实现约束：**

- 新增或重命名文件、目录统一使用 kebab-case；Nuxt 的 HTTP 方法后缀保留框架格式。
- AI 领域文件拆分为清晰的 API、repository、validation 和 service 边界。
- 注释解释数据流、权限、幂等、流式保存时机等设计原因，不添加无意义的逐行注释。
- RAG 只记录为后续迭代，不进入本任务验收范围。

**验收标准：**

- [ ] 会话和消息可以持久化到数据库，一个访客可以拥有多个会话。
- [ ] 会话和消息只能由所属匿名访客读取或删除；Cookie 过期后新身份无法读取旧历史。
- [ ] 点击“新建对话”不会产生空数据库会话；第一次发送消息时才创建会话。
- [ ] 首次发送后，当前会话标题无需刷新页面即可在侧栏显示，并与持久化后的标题一致。
- [ ] 前端发送请求只包含当前消息、会话标识和幂等 nonce，不包含完整历史数组。
- [ ] AI 回复以流式方式显示，完成后保存完整 assistant 消息。
- [ ] AI 回复按统一的 16ms 渲染节奏追加流片段，不因字符数量增加而产生累积延迟；思考阶段不显示输入光标，最终答案生成期间显示输入光标。
- [ ] 发送新消息时消息区域自动定位到底部并跟随回答；访客主动上滚后不再强制回底部，滚回底部后恢复自动跟随。
- [ ] AI 回复的 Markdown 标题、表格、分隔线和代码块可正确呈现；原始 HTML 不会执行，用户消息不会被作为 Markdown 渲染。
- [ ] AI 回复可呈现 `$...$`、`$$...$$`、`\\(...\\)` 与 `\\[...\\]` 公式、标记为 `mermaid` 的围栏图表和 `toml` 代码块；围栏代码和行内代码中的 LaTeX 字面量不被改写，Mermaid 图表位于带工具栏、无滚动条、图表居中的固定宽高独立画布且支持按钮或画布内滚轮缩放、左键拖拽平移、还原和下载 PNG，缩放和位移不会改变画布尺寸，公式与图表在窄屏不撑破消息区域，错误 Mermaid 源码可见。
- [ ] 当前千问模型和账号已确认支持时，页面显示深度思考胶囊按钮；关闭时向千问显式发送 `enable_thinking: false`，开启时发送 `true`，服务端禁用时拒绝开启请求。
- [ ] 深度思考流式增量与最终回答通过独立 SSE 事件 `reasoning_delta` 和 `answer_delta` 传输，思考完成事件携带耗时；思考内容持久化到 `reasoningContent`，耗时持久化到 `reasoningDurationMs`，最终答案持久化到 `content`；前端使用带背景和边框的可折叠信息块展示思考，生成期间标题为“正在思考”，完成后标题为“已思考（耗时）”，标题为 16px、内容为 12px Markdown，思考阶段不显示输入光标且不会混入最终答案。
- [ ] 获取历史消息时可同时恢复思考内容和最终答案；停止、失败或不完整回答不会保存半截 assistant 消息。
- [ ] 网络重试不会重复保存 user 消息；停止或失败时界面可重试且不伪造回答。
- [ ] RAG 和 Agent 工具不在本任务中实现；联网搜索仅按 Phase 6 的后续阶段接入。
- [ ] `qwen3.8-max` 联网搜索通过 DashScope 原生 `multimodal-generation` 流式接口调用；服务端传递 `enable_search`，并在搜索开启时传递 `search_options.enable_source: true` 以取得来源。服务端只读取现有的 `QWEN_API_KEY`。

## Phase 6：高级 AI 能力分阶段扩展

- [x] 1. **富内容展示：** 支持 KaTeX、Mermaid 与 TOML 高亮；不改变文本消息接口、会话数据或模型请求。
- [ ] 2. **深度思考：** 仅在已确认当前千问模型和账号支持时显示胶囊按钮；服务端通过 `reasoning_delta` 和 `answer_delta` 两类 SSE 事件分离思考增量与最终回答，并分别通过 `reasoningContent`/`content` 字段传输与持久化，前端折叠展示思考过程并支持历史消息恢复，不把它混入最终答案。
- [ ] 3. **联网搜索：** qwen3.8-max 使用 DashScope 原生 `multimodal-generation` 流式接口，服务端始终向千问明确传递 `enable_search: true/false`，并在开启时传递 `search_options.enable_source: true`；用户开启且当前千问模型/账号可用时，通过独立 SSE 事件转发 `search_info.search_results` 中的可信来源；`ai-search-sources` 在每条有来源的 assistant 消息底部展示“已搜索 N 个网页”触发器，点击打开侧边抽屉展示站点、标题、千问返回的摘要和安全链接，不额外抓取网页正文；来源不能由模型文本伪造。来源随 assistant 消息持久化并在幂等重试、历史恢复时回放；能力不可用时不显示开关，伪造请求会被服务端拒绝。
- [ ] 4. **图片与文档：** 新增受保护上传接口、对象存储、MIME/大小/内容校验和文件解析；消息模型改为图文内容数组，图片请求使用视觉模型，文档提取文本需限长、分段并记录来源。
